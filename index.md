# Welcome
  As I enter the computer science field as a professional, the strengths, skills, and values that I have developed and shown during my time at the SNHU computer science program are important to highlight. Some of this will be showcased in this portfolio, with work that I did during the program now enhanced with new functionality to show my improved abilities. But there is also work not present that presents these attributes as well, and they are also important in assessing my current expertise. One skill to discuss is my abilities in collaborating in a team environment. Although I did not directly work with others during the program, I did exhibit my ability to do so and the understanding of what goes behind that. For instance, I learned and experienced concepts such as the software development life cycle, Agile, Kanban, and Scrum. Also, I took part in different simulated team roles to experience the importance of each person on a Scrum team. Being able to work within these scenarios, revise and complete code that was worked on before me and understanding and writing documentation for code are things that I have done throughout these past few years with the program. They have prepared me for, and given me experience in, fostering collaborative environments that I can carry with me into a professional context.
  Paired with this, I have done extensive work in improving and exhibiting my ability to communicate with stakeholders. Some of this will be shown in this portfolio, but outside of this I have written thorough papers and documentation for the program. This includes creating full READMEs for programs and explaining my work and intentions for many courses. I also have done some recorded videos to do the same, specifically to discuss code for game development. This has developed skills in being able to clearly explain myself in multiple formats and maintain effective communication practices, while also tying back with understandings of the SDLC and the relationship between stakeholders and developers.
	For these next points, I will be presenting artifacts specifically focused on them in this portfolio. But, to also go over work done outside this portfolio, data structures and algorithms were something I was thoroughly introduced to during the program. Concerning algorithms, pseudocode, flowcharts, and diagrams were extensively worked with, for multiple programs and algorithms. This gave better insight into how data flows in a program and how to write more efficient code. That work also connects to testing different algorithms in C++, such as a binary search tree and hash table algorithm, giving perspective on the different use-cases for them and the importance of efficiency when working with big data. This also involved working with different data structures, including outside C++, based on the situation. Programming and designing solutions to logic problems using different algorithms is a skill I continue to improve at, and hope that is represented in the artifacts here as well.
	Using and understanding well-founded and innovative skills and tools was also something frequently demanded during the program, highlighting my software engineering capabilities. Following the software development life cycle, even within the bounds of assignments, and learning more on industry-standard software designs and processes helped increase the quality of my work. For industry-standard techniques, practices such as iterative testing were done to ensure code was being developed properly. Also, architectural patterns were frequently used for larger applications, particularly the model-view-controller pattern that I implemented in a mobile application. With the software development life cycle, as already mentioned I took the place of multiple team roles in simulated scenarios. But in addition to that, I’ve done analysis of requirements and design constraints for different proposed applications and used that to determine realistic production timelines. This also involved working with databases in various contexts, and becoming proficient at using MongoDB in particular, which will be exhibited with an artifact in this portfolio. Finally, general use of standard tools for different projects and coding practices was reinforced throughout my time at SNHU, and I have refined my skills from that.
	Maintaining a secure mindset is also regularly critical to developing good code. Secure coding practices were always emphasized, and work was done on some good practices such as developing automated tests, error handling, and implementing input validation and sanitization. During iterative testing, finding and resolving bugs and unintended behavior was a frequent necessity. In addition to this, some courses specifically had me seeking vulnerabilities and running tests to improve security. Learning about different practices to mitigate vulnerabilities like checking for dependencies and following basic coding principles was useful in making better code. Implementing some means of checking inputs, trimming or restricting them to intended inputs, and encapsulating code to limit harm on the program were some ways of handling this. Also, keeping code well documented and maintainable by people in the future factor in this too, emphasizing the need to follow standard practices. These basic skills discussed have all been refined during my time at SNHU and are translatable into a professional setting.
	Most of my work at the SNHU program that I have mentioned will not be present in this portfolio, as they span multiple years and are not all up to my current standards. Instead, I have focused on three specific artifacts of code that show my skill in different areas, enhancing that code to add better functionality and more robust code. Also, I have a code review recorded prior to the enhancements where I reflect on the prior state of the projects, and written narratives to discuss them in greater detail. To briefly go over them, my first artifact is a terminal program to manage different types of support animals, containing code for different attributes of the animals and code for a basic user-friendly means of adding, updating, and deleting them from tables. It was created for one of my earliest courses, IT-145, and was enhanced to show software engineering skills. This is presented as part of my new files for the artifact, with code translated from Java to Python, additionally overhauled to both follow Python’s different practices and refactored to be generally better coded, with more robust and efficient code while preserving the original functionality. My second artifact is a series of services for managing specific entities from classes, such as appointments, contacts, and tasks, along with a driver program. This was made for CS-320 and has been enhanced to show skills with data structures and algorithms. It was enhanced by rewriting the service classes to use HashMaps instead of basic lists to hold their respective entities, using HashMap algorithms to create more efficient code, adding better error handling and input validation for the entities, and implementing the driver program to highlight the time spent for each function. Finally, the last artifact will be a web dashboard to display rescue animals from a MongoDB databases. This was created for a recent course, CS-340, and includes a user-friendly dashboard along with filters and visualizations for animal locations and proportions of animal breeds, out of what’s selected. This was enhanced to show capabilities with databases by adding an additional panel to manage the database directly from the web application, supporting functions such as adding new animals, updating fields of animals already present, and deleting animals, while also refreshing the dashboard in real time. Additionally, functionality was included to add animals from a csv into the database. All of this was meant to be an alternative to using MongoDB directly, either over the terminal or another application, and shows proficiency for interacting with databases. These are the artifacts that will be presented directly in the portfolio, but all of what I’ve discussed understanding of during this self-assessment should be reflected throughout.
